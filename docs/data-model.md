# WMP 数据模型与生命周期约束

## 核心关系

- 项目与版本、机台、子系统均为一对多。
- WKD 仅属于一个项目、一个所属版本和一个子系统，可关联多个机台。
- 新建时，项目与所属版本由全局上下文自动带入；创建后项目、所属版本均不可修改。
- 责任人固定为新建此 WKD 的当前用户，不另设创建人字段，后续不可修改。
- 每个 WKD 同一时间最多只有一个当前处理人：`NEW_WKD`、`VERIFY` 为责任人，`REVIEW`、`DISABLE_CONFIRM` 为指派软件经理，`APPROVED`、`DISABLED` 为空。
- 自动化执行的 WKD 只有一个执行阶段，可包含多个有序原子操作；所有机台共用该配置。
- 构建制品与 WKD 为多对多，通过制品明细保存执行顺序和不可变快照。

## 表格字段与筛选偏好

- 工作台、调试构建、正式构建共用 WKD 表格字段模型；WKD 编号与标题固定显示，其余字段由用户按需勾选。
- 字段偏好仅保存在浏览器 `localStorage`，键按“用户 + 表格类型”隔离，不写入业务数据库，也不新增后端接口；清除浏览器站点数据后恢复默认列。
- 表头筛选支持多选、选项关键字搜索、当前搜索结果全选与清空；工作台筛选由后端查询完成，构建页在当前可构建数据内筛选。
- 执行类型、活动场景、措施类型、执行阶段和工作流状态均支持表头多选筛选；工作台对应查询参数为 `execution_types`、`activity_scenes`、`measure_types`、`stages`、`statuses`。

## WKD 关键校验

1. 问题单号与需求单号至少填写一项，单项最长 100 字符；填写问题单号时，问题发现版本必填。
2. 执行类型为 `AUTOMATED` 时，执行阶段和至少一个原子操作必填；`MANUAL` 的阶段与原子操作为空，前端切换前必须提示清空。
3. 自定义阶段名称在当前所属版本下唯一，最长 100 字符，且必须匹配 `^[A-Za-z][A-Za-z0-9_.-]*$`，可直接作为后续执行脚本的阶段参数；普通阶段会自动清空自定义阶段名。
4. WKD 编号为 `WKDYYYYMMDD + 四位当日序号`，每日从 `0001` 重置，使用事务与唯一约束避免并发重号。
5. 附件单文件最大 500 MB，每个上传会话最多 100 个；实际内容存 RustFS，数据库保存 Object Key 与文件元数据。
6. 每次进入状态均形成独立历史面板；状态说明支持安全富文本、字体颜色和内嵌粘贴图片，单张图片最大 5 MB。
7. 创建后的普通“保存本地草稿”仅写当前标签页的浏览器存储，按“用户 + WKD + 当前状态次数”隔离，不请求后端、不产生历史；首次创建和状态流转才提交后端。含原子文件的草稿超过 4 MB 时明确拒绝本地保存，避免静默超过浏览器配额。
8. `submit_verify`、`submit_review` 必须携带完整 WKD 数据，后端在流转事务中记录所有可变业务属性的前后值，包括关联机台、执行阶段和原子操作编排。
9. `wkd_history.changes` 使用 JSONB 保存结构化变更数组，每项包含 `field`、`label`、`before`、`after`；详细流程只展示说明与流转意见，完整历史展示属性变化。
10. `submit_review`、`request_disable` 必须传入 `manager_id`，且候选人必须是当前项目内具有 `wkd.review` 权限的启用用户；没有项目成员关系时，可由全局角色提供该权限。处理人变化写入历史记录。
11. 所有状态流转都必须携带 `lock_version >= 1`。后端以 `SELECT ... FOR UPDATE` 锁定 WKD 后比较版本，状态或处理人变化时递增版本；缺失、过期版本分别返回 `422`、`409`，避免并发覆盖。
12. 停用项目与“用户初始化”项目禁止新业务；归档所属版本、停用子系统、停用机台不能用于新建或重新编辑业务关系，历史关联数据仍可查看和追溯。

## 附件上传会话与创建一致性

- `upload_sessions` 记录项目、上传人、可选既有 WKD、状态和过期时间，默认 24 小时；新建 WKD 会话要求 `wkd.create`，既有 WKD 会话统一经过状态与权限校验，会话及草稿附件仅上传人可操作。
- 既有 WKD 在 `NEW_WKD`、`VERIFY` 中仅允许当前处理人上传，且必须同时具有 `wkd.edit`、`files.upload`；`APPROVED` 允许具有 `files.upload` 的项目用户受控补传资料；`REVIEW`、`DISABLE_CONFIRM`、`DISABLED` 一律返回 `409`，禁止上传。系统管理员仍需满足编辑阶段的处理人例外规则以外的权限约束。
- 会话初始化、分片地址申请和完成上传都会重新检查 WKD 当前状态并锁定 WKD，旧会话不能跨状态完成上传。附件补传是受控资料变更，不修改业务字段、不触发状态流转，也不递增 `lock_version`。
- 附件初始化即写入 `UPLOADING` 元数据，后端向 RustFS 核实对象和实际大小、接收前端流式计算的 SHA-256 后才转为 `READY`。小于 64 MB 默认单次直传，达到阈值后使用 16 MB 分片；分片完整性和 ETag 由完成接口校验。
- 新建 WKD 请求显式携带 `attachment_ids`，只绑定当前用户、当前项目、未绑定且状态为 `READY` 的草稿附件，不是绑定会话内全部文件。附件绑定与 WKD 元数据在同一数据库事务中提交，RustFS 对象不属于该事务。
- 创建请求可携带 `idempotency_key`；服务端保存请求哈希，同一用户、同一键和同一请求返回已有 WKD，同键不同请求返回 `409`，防止网络重试产生重复单据。
- 后端启动后每小时清理过期未绑定附件、未完成上传及过期分片；已绑定的 `READY` 附件不随会话过期删除。对象存储 Bucket 还应配置未完成分片生命周期清理作为兜底。
- 旧的 `/files/upload-url`、`/files/complete` 仅保留给既有 WKD 的兼容单次上传，不再接受未关联 WKD 的上传。

## 状态定义

| 状态 | 中文 | 编辑能力 | 允许的流转 |
|---|---|---|---|
| `NEW_WKD` | 新建规避措施 | 本地编辑 | 本地保存、提交自验证、禁用 |
| `VERIFY` | 自验证 | 本地编辑 | 本地保存、提交软件经理审核、禁用 |
| `REVIEW` | 软件经理审核 | 全部锁定 | 审核通过、审核驳回 |
| `APPROVED` | 审核通过 | 业务字段只读，允许受控补传附件 | 发起软件经理确认禁用 |
| `DISABLE_CONFIRM` | 软件经理确认禁用 | 全部锁定，禁止上传附件 | 确认禁用、拒绝禁用 |
| `DISABLED` | 禁用 | 最终只读，禁止上传附件 | 无 |

审核通过与驳回均必须填写审核意见；驳回回到 `VERIFY`。`APPROVED` 不能直接禁用，必须选择软件经理进入 `DISABLE_CONFIRM`；确认禁用进入 `DISABLED`，拒绝禁用返回 `APPROVED`。禁用申请和确认意见均必填。WKD 不允许取消或删除；审核通过后的业务字段变更只能禁用后重建，普通附件补传按附件章节的独立规则执行。

## 权限与文件

- 用户为平台级身份，有效项目角色按“具体项目成员角色优先，无该项目成员关系时回退全局角色”解析；鉴权、项目列表、基础选项、责任人和审核人选项共用该语义。
- 成员管理的“所有项目”为独立全局授权：`users.global_role_id` 指向一个非系统管理员角色模板，不创建 `project_members` 记录，不覆盖已明确分配的项目角色；仅系统管理员可授予、调整或撤销。全局软件经理可成为各项目审核人。
- 系统管理员拥有全局权限且仅使用本地管理员登录；其他用户通过企业 OIDC 完成身份验证，业务权限由 WMP 本地分配。
- 项目、平台用户、全局角色模板和全局审计日志仅由系统管理员管理，这些全局能力不进入项目角色的权限点。
- 项目管理员仅在当前项目内维护版本、机台、子系统和成员，可查看并分配角色模板，但不能创建项目或修改全局角色权限。
- 业务数据使用 `business.version.*`、`business.machine.*`、`business.subsystem.*` 权限；成员与角色分配使用 `project.member.*`，角色模板只读使用 `project.role.view`。
- 系统管理员不是可分配的项目角色；项目管理员不能修改或移除已有系统管理员成员；项目必须至少保留一名项目管理员。项目内业务数据禁止转移到其他项目。
- 用户档案只保留 `username`、`employee_id`、`department`、`email` 等业务字段，不再设置“姓名”；`employee_id` 全局唯一，`username` 仅用于展示、允许重复。
- OIDC 使用授权码、State、Nonce 和 ID Token 签名校验；已导入用户首次只按工号绑定 `sub`，后续按 `sub` 识别，缺少工号时不得退化为按用户名绑定。未注册的企业用户自动创建平台账号，并加入按需创建的“用户初始化”占位项目（code：`WMP-USER-INIT`）。内置“初始化用户”角色仅含 `home.view`，不包含任何实际业务权限，也不能通过成员管理、全局授权或角色编辑接口分配和修改；后续真实项目权限仍由项目管理员分配。
- “用户初始化”项目只用于账号落地，不承载实际业务。包括系统管理员在内，任何用户都不能在该项目中创建或流转 WKD、执行调试／正式构建、维护版本／机台／子系统；全局项目、成员和角色管理保持可用，处理实际业务前必须切换到真实项目。
- 项目成员批量初始化使用五列模板：工号（必填）、用户名（必填）、所属部门（选填）、项目角色（选填）、邮箱（选填）。单次最多 5000 行，先解析校验并预览，全部无错误后才能确认写入；已有项目成员保留原角色，已有平台用户只新增当前项目成员关系，不重复创建用户。
- 批量初始化接口要求目标项目的 `project.member.manage`：系统管理员可导入任意项目，项目管理员只能导入自己有权维护的项目；系统管理员和初始化用户角色不可通过导入分配。
- 查询与刷新共用模块查看权限，其他按钮使用独立权限点。
- 所有接口在服务端鉴权；重要操作写审计日志。
- RustFS Bucket 私有，上传下载由后端鉴权后签发短时预签名地址。

## 数据统计边界

- 数据统计对所有已登录用户开放，不配置角色权限点；未登录访问仍返回 `401`。
- 项目统计必须明确选择一个项目；全局统计支持跨项目多选汇总与项目对比，查看和导出均不校验项目成员或角色。
- 所有筛选条件共同作用于统计指标、趋势、分布、明细和 XLSX 导出；多选条件为组内 OR、组间 AND，机台多选匹配任一关联机台。
- 创建或更新时间范围最长 366 天；趋势按 31 天以内日、93 天以内周、更长周期月聚合。
- “当前审核通过占比”按当前状态为 `APPROVED` 的记录数除以筛选总量；待处理包含 `VERIFY`、`REVIEW`、`DISABLE_CONFIRM`；平均处理时长取创建至首次审核通过。
- 新增趋势按 WKD 创建事件统计；审核趋势按 APPROVE 历史事件发生时间独立统计，以前创建、本周期审核的记录计入本周期。导出为标准 `.xlsx` 工作簿，包含冻结表头、自动筛选和适配列宽；后端通过临时文件缓冲流式返回，并中和公式危险前缀。当前指标、分布与明细仍在应用层全量聚合，明细尚未后端分页，大数据量场景需继续优化。

## 原子操作与构建制品结构

- `UPLOAD_FILE` 支持在单个操作内通过 Upload 组件从本地多选实际文件，公共参数为目标目录 `target_path`、覆盖策略 `overwrite`、权限 `permission`；每个操作包含 1～100 个文件，每项包含 `name`、`content` 和 `size`，同一操作内文件名不可重复，单文件上限 20 MB，单 WKD 原子文件总量上限 100 MB。
- 新选择的文件以 `encoding=base64` 和 Base64 `content` 保存原始字节，构建时解码并按原内容写入制品，支持文本及二进制文件；无 `encoding` 的历史数据仍按 UTF-8 文本处理。审计历史只记录文件名和大小，不展开文件内容。
- `LINUX_COMMAND` 包含 `command`、`workdir`、`timeout`、`exit_code`，不包含环境变量参数；`workdir` 必须为安全绝对路径，超时为 1～86400 秒，期望退出码为 0～255。`SCRIPT` 包含 `script_type`、`script`、`arguments`、`timeout`，仅支持 Python 和 Shell 脚本。
- 构建产物为真实 `tar.gz`，不依赖 Jinja2 或目标机第三方包，通用入口仅使用 Python 标准库。制品结构如下：

```text
wmp_entry.py                         # 通用入口脚本
WKD_LIST.json                        # WKD 属性、原子操作编排及附件清单
MANIFEST.json                        # 制品索引、子包路径、阶段参数及附件数量
README.md                            # 入口使用说明
packages/<WKD编号>/package.json      # 不可变 WKD 快照、执行清单及附件元数据
packages/<WKD编号>/files/...         # 原子操作上传的实际文件
packages/<WKD编号>/attachments/...   # WKD 普通附件，按附件序号隔离
```

- 自动化和人工操作 WKD 均允许构建。人工 WKD 保留属性与普通附件，不要求阶段或原子操作；`--list` 将其阶段显示为“人工操作”。
- 构建仅包含已绑定所选 WKD 且状态为 `READY` 的普通附件。后端从 RustFS 流式读取附件、校验实际大小和 SHA-256，再流式写入制品并上传，不把整个大制品一次性载入内存。
- 单次构建包含 1～200 个不重复 WKD，普通附件总量默认最多 2 GB（`MAX_BUILD_ATTACHMENT_BYTES`）。当前构建仍是同步请求，无任务进度和幂等；RustFS 上传后数据库失败会补偿删除对象。
- 普通附件只作为随包资料保存，入口不会自动执行或安装；原子操作文件与普通附件分别存放在 `files/` 和 `attachments/`，互不混用。
- 通用入口默认执行方式为 `python3 wmp_entry.py <阶段参数>`；`python3 wmp_entry.py --list` 只列出包内 WKD 和阶段，`python3 wmp_entry.py <阶段参数> --wkd <WKD编号>` 仅执行一个 WKD。旧的 `python3 wmp_entry.py <WKD编号> <阶段参数>` 调用保持兼容。
- 普通阶段参数使用 `pre_upgrade`、`post_upgrade`、`post_start`、`post_init`；自定义阶段直接使用用户定义的、当前版本下唯一的阶段名称。
- 默认整包执行按 `MANIFEST.json` 的子包顺序运行，该顺序由构建后端按 WKD 登记时间 `created_at` 升序生成；不匹配阶段的子包自动跳过，没有匹配项时返回错误。
- 每个子包内部按原子操作 `position` 升序执行；上传文件会校验 SHA-256，任一操作失败即停止后续执行并返回非零退出码。
