# WMP v1.5 差异梳理与代码阅读指南

本文面向需要快速理解本次升级的内网 AI、研发与运维人员，说明当前 v1.5.0 相比**首次上传 GitHub 的 v1.4 基线**发生的主要变化。本文是导航和升级说明，不替代接口、数据模型及部署文档。

## 1. 对比范围

- 首次上传基线：`f7ccde0c143e9b9432cd4c19cd9fd832f6dc301e`
- 基线提交说明：`feat: WMP v1.4 lifecycle, executable builds and OIDC`
- 对比终点：本次 WMP v1.5.0 提交。
- 对比方式：以基线提交中的文件内容与当前工作树逐文件比较，而非只根据提交说明推断。
- 基线之后已有两个中间提交：安全 GitHub 上传工作流、统计与界面可读性改进；v1.5 还包含其后尚未进入首次基线的认证、权限、成员导入、附件、表格和登录安全改动。

## 2. 一句话理解 v1.5

v1.4 已具备 WKD 生命周期、原子操作、可执行构建包和 OIDC 基础能力；v1.5 重点补齐了**企业用户落地与项目授权、生产登录安全、新建前附件、批量成员初始化、开放的多维统计、统一表格偏好，以及部署和回归测试**。

## 4. 认证、用户与初始化项目

### 4.1 生产登录边界

- 生产前端不预填管理员账号，不显示角色选择，也不允许 Demo 降级；生产构建始终忽略 Demo 会话。
- Demo 登录仅在 `import.meta.env.DEV` 且 `VITE_ENABLE_DEMO_LOGIN=true` 时可用。
- 后端再次执行生产登录限制：本地账号只有系统管理员可以登录，普通用户必须使用企业 OIDC。
- 系统管理员不能通过 OAuth 登录，避免企业身份绕过本地最高权限账号边界。
- 登录页和侧边栏不向用户展示工程版本号；v1.5.0 只体现在工程元数据、健康检查和接口文档中。

### 4.2 用户唯一标识变化

- `employee_id`（工号）是全局唯一标识，OIDC 首次绑定和批量导入均以工号为依据。
- `username` 只用于展示，允许重复，不能作为 OIDC 自动绑定依据。
- 删除旧 `name`（姓名）字段，新增 `department`（所属部门，选填）。
- 已导入用户首次 OIDC 登录按工号绑定 `sub`，后续按 `sub` 识别；缺少工号时不能退化为按用户名绑定。

### 4.3 自动注册与隔离

- 未注册的企业用户 OIDC 验证通过后自动创建 WMP 用户。
- 自动创建的用户进入按需生成的“用户初始化”占位项目，项目 code 为 `WMP-USER-INIT`。
- 内置“初始化用户”角色仅含 `home.view`，不能用于真实业务，也不能通过普通成员、全局角色或角色编辑接口分配和修改。
- 包括系统管理员在内，任何用户都不能在初始化项目中创建／流转 WKD、构建或维护版本、机台、子系统；全局项目、成员和角色管理仍可使用。
- 用户获得真实项目角色后，应切换到真实项目处理业务。

## 5. 权限与成员管理差异

### 5.1 全局和项目权限分离

- 系统管理员负责项目、平台用户、全局角色模板、所有项目授权和全局审计。
- 项目管理员只维护项目内的版本、机台、子系统、成员及角色分配，不能创建项目或修改全局角色权限。
- “所有项目”是独立全局授权，保存于 `users.global_role_id`；它不会创建各项目的 `project_members` 记录，也不覆盖具体项目角色。
- 仅系统管理员可授予、调整或撤销所有项目角色；被全局授权使用的角色不能删除。
- 项目管理员不能修改或移除已有系统管理员成员；项目必须至少保留一名项目管理员。
- 业务数据不允许转移到其他项目；前端隐藏或禁用按钮不能替代服务端鉴权。

### 5.2 Excel／CSV 批量初始化

模板固定为五列：

1. 工号：必填，唯一标识。
2. 用户名：必填，允许重复。
3. 所属部门：选填。
4. 项目角色：选填，为空时使用页面默认角色。
5. 邮箱：选填。

导入采用“下载模板 → 上传并预览 → 全部行无错误 → 确认导入”的两阶段流程。确认接口会重新鉴权和校验，不信任前端预览结果。已有项目成员保留原角色，已有平台用户只增加成员关系，新用户按工号创建。单次最多 5000 行，文件最大 10 MB；系统管理员和初始化用户角色不可通过导入分配。

## 6. WKD 生命周期与编辑边界

### 6.1 六种独立状态

```text
NEW_WKD → VERIFY → REVIEW → APPROVED → DISABLE_CONFIRM → DISABLED
             ↑          │                   │
             └── 驳回 ──┘                   └── 拒绝禁用返回 APPROVED

NEW_WKD / VERIFY 可直接禁用为 DISABLED；APPROVED 必须先进入 DISABLE_CONFIRM。
```

- `REVIEW` 只处理审核通过或驳回；`DISABLE_CONFIRM` 只处理确认禁用或拒绝禁用，二者不混用。
- `NEW_WKD`、`VERIFY` 的当前处理人为责任人；`REVIEW`、`DISABLE_CONFIRM` 为被指派的软件经理；`APPROVED`、`DISABLED` 无待处理人。
- 提交审核和发起禁用必须选择具有 `wkd.review` 权限的项目成员。
- 非系统管理员只能由当前处理人执行其当前状态允许的操作；审核、驳回、禁用申请和确认意见均按要求必填。

### 6.2 本地草稿与正式历史

- 首次创建调用后端；创建后的普通“保存”只写浏览器本地草稿，不更新数据库，也不生成历史。
- 后端正式业务写入发生在首次创建和状态流转，不提供普通详情覆盖保存接口。
- `submit_verify`、`submit_review` 携带完整 WKD 字段、原子操作和 `lock_version`；`submit_review` 还必须携带 `manager_id`。
- 每次进入状态形成独立流程面板；历史同时保存状态说明和结构化属性差异 `changes`。
- 项目、所属版本来自全局上下文；责任人固定为新建人。创建后项目和所属版本不可修改。
- 详细流程、附件、历史记录是三个独立标签；当前待编辑状态面板展开，其他面板默认折叠。

## 7. 附件与原子操作差异

### 7.1 新建前附件上传

- 新建 WKD 前先创建上传会话，不再要求“首次保存后才能上传”。
- 草稿附件仅上传人可恢复、下载、取消和绑定；跨用户、跨项目、过期或状态不正确的附件会被拒绝。
- 小于 64 MB 默认单次直传，达到阈值后使用 16 MB 分片；浏览器需要读取 RustFS 返回的 `ETag`。
- 完成接口核验对象和实际大小，并保存前端流式计算的 SHA-256，附件随后进入 `READY`。
- 创建 WKD 时通过 `attachment_ids` 显式绑定已完成附件，并通过 `idempotency_key` 防止网络重试重复建单。
- 上传会话默认 24 小时过期，后端默认每小时清理过期未绑定附件和未完成分片；已绑定附件不随会话过期删除。
- RustFS 只保存对象，PostgreSQL 只保存 Object Key 和元数据；备份与恢复必须覆盖两者。

### 7.2 多文件原子操作与构建

- `UPLOAD_FILE` 在一个操作内通过 Upload 组件选择多个真实文件，不再让用户手工填写文件名或文本内容。
- 新文件以 `encoding=base64` 保存原始字节，支持文本与二进制；无 `encoding` 的历史数据仍按 UTF-8 文本兼容。
- 单文件上限 20 MB，同一操作内文件名不可重复；公共参数为目标目录、覆盖策略和权限。
- 构建包包含 `wmp_entry.py`、`MANIFEST.json`、`WKD_LIST.json`、`README.md` 和 `packages/<WKD编号>/`。
- 目标机执行方式为 `python3 wmp_entry.py <WKD编号> <阶段参数>`；入口只依赖 Python 标准库，上传文件执行前校验 SHA-256。
- 普通阶段参数为 `pre_upgrade`、`post_upgrade`、`post_start`、`post_init`；自定义阶段使用当前版本内唯一的用户定义名称。

## 8. 统计与通用表格差异

### 8.1 数据统计

- 项目统计必须选择一个项目；全局统计支持多项目或全部项目。
- 所有已登录用户均可查询筛选项、查看统计和导出 CSV，不配置角色权限点；未登录仍返回 `401`。
- 多选条件包括项目、所属版本、问题发现版本、规划解决版本、机台、子系统、状态、执行类型、活动场景、措施类型、责任人、当前处理人与执行阶段。
- 关键字匹配 WKD 编号、标题、问题单号和需求单号；支持创建／更新时间范围，单次最长 366 天。
- 同一筛选条件共同作用于指标、趋势、分布、项目对比、明细和导出。

### 8.2 表格与筛选偏好

- 工作台、调试构建和正式构建采用统一表格能力。
- WKD 编号与标题固定，其余列由用户勾选；执行类型、活动场景、措施类型等关键字段均可配置。
- 表头筛选支持多选、输入搜索、当前结果全选和清空；工作台走后端筛选，构建页在可构建集合内筛选。
- 列偏好只存浏览器 `localStorage`，键按“用户 + 表格类型”隔离，不写入业务数据库，不新增偏好 API。
- 新增工作台查询参数 `execution_types`、`activity_scenes`、`measure_types`；既有 `stages`、`statuses` 等多选筛选保持统一语义。

## 9. 数据库与接口升级重点

### 9.1 结构变化

- 新增 `upload_sessions` 表，附件增加上传会话、状态、分片标识、存储上传 ID 和更新时间。
- 用户增加 `global_role_id`、`department`，删除 `name`，取消用户名唯一约束；工号继续唯一。
- WKD 增加 `current_handler_id`、`creation_key`、`creation_hash`。
- `wkd_history` 增加 JSONB `changes`；`wkdstatus` 枚举增加 `DISABLE_CONFIRM`。
- 启动时通过 `create_all`、幂等 `ALTER` 和索引语句补充结构，当前仍未引入 Alembic。

### 9.2 主要新增接口

- OIDC：`POST /auth/oauth/login`、`POST /auth/oauth/callback`。
- 统计：`GET /statistics/options`、`GET /statistics`、`GET /statistics/export`。
- 所有项目授权：`GET /global-access/users`、`PUT /users/{user_id}/global-role`。
- 成员导入：模板下载、`bulk-preview`、`bulk-import` 三个项目成员接口。
- 草稿附件：上传会话创建／恢复、附件初始化、分片地址、完成与取消接口。

完整路径、请求体和响应模型以 `docs/api.md`、`docs/openapi.json` 以及运行时 `/openapi.json` 为准。

### 9.3 升级风险

- 生产升级前必须同时备份 PostgreSQL 和 RustFS，并先在测试环境使用同结构数据验证启动迁移。
- 数据库账号在启动阶段仍需建表、修改表、修改枚举和维护索引的权限。
- 删除 `users.name`、取消用户名唯一约束及新增枚举后，不能假设任意旧代码可直接回滚到升级后的数据库。
- 生产本地登录策略变更是有意为之：普通本地账号会返回 `403`，不是 OIDC 配置回退入口。
- 生产 `SEED_DEMO_DATA=false`；测试和生产数据库、Bucket、JWT 密钥、OIDC Client 与管理员密码必须隔离。

## 12. 推荐给内网 AI 的阅读顺序

1. 先读本文，建立 v1.4 → v1.5 的整体差异模型。
2. 读 `docs/data-model.md`，确认字段、状态机和权限边界。
3. 读 `docs/api.md` 与 `docs/openapi.json`，确认真实接口契约，不要根据页面推测接口。
4. 按任务进入对应模块：认证看 `oauth.py`／`auth.py`，权限看 `deps.py`／`admin.py`，附件看 `attachment_service.py`／`files.py`，WKD 看 `wkd.py`／`WkdDetailView.vue`。
5. 涉及上线时必读 `docs/deployment.md`，尤其是数据库迁移、生产登录、RustFS CORS、备份和回滚约束。
