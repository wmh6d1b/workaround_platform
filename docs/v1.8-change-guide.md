# WMP v1.8 差异、部署与代码理解指南

本文面向内网 AI、研发和运维人员，说明当前 **v1.8.0** 相比 GitHub **v1.7.0** 的累计变化。行为结论来自当前代码与测试，精确逐行差异见 `docs/v1.8-full.diff`。

## 1. 对比基线与阅读方式

- 基线提交：`5a0841dfb54e7ed38a52fdc745888093ea5d902a`（`release: WMP v1.7.0 文档与首屏稳定性完善`）。
- 中间小提交：`3d65c04`（登录页品牌区居中、新增本地开发服务一键脚本 `scripts/dev-services.sh`）。
- 当前版本：v1.8.0，重点修复内网部署暴露的两个严重后端缺陷（机台状态枚举、并发行锁），并补齐新建 WKD 草稿、幂等重试与一批交互细节。
- 接口以 `docs/api.md`、`docs/openapi.json` 为准；部署以 `docs/deployment.md` 为准，不要根据页面或历史文档推测。

## 2. 一句话理解 v1.8

v1.8 不新增业务模型和接口，主要做两件事：**修掉内网部署发现的两个 P0 后端缺陷**（机台状态枚举缺失导致无法新建机台、`FOR UPDATE` 与 ORM join 冲突导致状态流转报错），以及**把新建 WKD 的"草稿、幂等、拖拽"三个交互做完整**。

## 3. v1.7 → v1.8 用户可见行为差异

| 场景 | v1.7 | 当前 v1.8 |
|---|---|---|
| 系统管理-机台管理新建/编辑机台 | 提交 `RUNNING`/`MAINTENANCE` 被后端 422 拒绝（枚举缺失，默认状态即失败） | 按资源类型校验：机台 `RUNNING/MAINTENANCE/STOPPED`、版本 `DEVELOPING/RELEASED/ARCHIVED`、项目/子系统 `ENABLED/DISABLED`，非法值返回 422 并列出合法值 |
| 给机台填版本类状态（如 `DEVELOPING`） | 共用枚举不拦截 | 422 拒绝，提示该机台支持的枚举 |
| WKD 状态流转 / 附件完成上传 | 内网 PostgreSQL 报 `FOR UPDATE cannot be applied to the nullable side of an outer join`，操作失败 | `FOR UPDATE OF wkds` 只锁主表，功能正常 |
| 新建 WKD 填了一半离开 | 无草稿能力，只能"保存并创建" | 新增「保存草稿」按钮（仅写浏览器 localStorage）；再次进入新建页自动恢复；检测到其他页面保存的草稿时弹覆盖确认 |
| 创建 WKD 失败后修改内容重试 | 报 409"同一幂等键不能用于不同的创建请求" | 幂等键改为创建内容哈希：内容不变重试自动命中原键（防双击重复创建），内容修改自动换新键 |
| 首页右上角 | 「登记 WKD」按钮 | 移除，统一从工作台「新建WKD」进入 |
| 原子操作编排 | 整张卡片可拖拽，选中输入框文本易误触发拖拽 | 仅左上角拖拽手柄可拖拽；标题栏显示"已添加 X 个操作"计数；拖拽中卡片半透明虚线反馈 |
| WKD 详情属性面板 | 基本信息 → 业务归属 → 执行属性；备注输入框；关联机台只能下拉选择 | 执行属性上移到基本信息之后；删除备注框（由详细流程富文本承载）；关联机台支持输入过滤、多选标签折叠 |
| 登录页左侧品牌区 | 水平方向偏左 | 在左半面板水平垂直居中 |
| 本地开发环境启动 | 手工分别启动 PostgreSQL/RustFS/前后端 | `./scripts/dev-services.sh start/status/stop` 一键管理四个本地服务（含就绪探测与日志） |

## 4. v1.8 关键实现说明

### 4.1 业务资源状态枚举按资源校验（后端）

- `backend/app/schemas.py`：`EntityInput.status` 扩为全量合法枚举并改为可选（`None` 时由各模型默认值兜底，各模型默认值恰好是各自合法值首位）。
- `backend/app/routers/admin.py` 新增 `RESOURCE_STATUSES` 与 `validate_resource_status()`，在 `create_business` / `update_business` 中按 `projects/versions/machines/subsystems` 分别校验，422 提示合法集合。
- 回归测试：`backend/tests/test_v16_regressions.py` 的 `ResourceStatusValidationTests`（机台接受三类合法值、拒绝其他资源状态、版本/项目状态集互相隔离）。
- 注意：`seed.py` 的初始化项目仍直接写 `INITIALIZING`，不走 `EntityInput`，行为不变。

### 4.2 并发行锁修复（后端）

- 根因：`Wkd` 有 7 个 `lazy='joined'` 关系（项目、三个版本、子系统、责任人、处理人），`db.get(Wkd, ..., with_for_update=True)` 生成的 SQL 带 LEFT OUTER JOIN，PostgreSQL 禁止对 outer join 的 nullable 侧加 `FOR UPDATE`。
- 修法：两处加锁改为显式查询 `db.scalar(select(Wkd).where(Wkd.id == ...).with_for_update(of=Wkd))`，生成 `FOR UPDATE OF wkds`，只锁主表行，锁语义与原设计一致。位置：`backend/app/routers/wkd.py`（状态流转）、`backend/app/attachment_service.py`（上传会话复核）。
- **不要**采用 `db.get(..., with_for_update(of=Wkd))` 的写法——`Session.get()` 不支持 `of` 参数，会抛 `TypeError`。
- 相关断言行锁的测试（`test_v16_regressions.py`、`test_initialization_project.py`）已同步改为 mock `db.scalar`。
- `backend/app/routers/admin.py` 锁 `Project` 的 `db.get(..., with_for_update=True)` 不受影响（`Project` 无 joined 关系，单表查询）。

### 4.3 新建 WKD 本地草稿（前端）

- `src/views/WkdDetailView.vue`：
  - 新增 `saveDraftOnly()`，新建态「保存草稿」按钮仅写 localStorage（复用 `src/utils/wkdDrafts.ts`，单槽位、4 MB 上限不变），不调后端。
  - 冲突保护：用 `lastDraftSavedAt` 记录本标签页最后写入/恢复的草稿时间，保存时发现已有草稿且时间戳不一致（来自其他页面）先弹 `ElMessageBox` 确认再覆盖。
  - `restoreLocalDraft()` 恢复时记录来源时间，提示语带保存时间。
- 边界：草稿仅存当前浏览器；附件不随草稿恢复（附件绑上传会话，24 小时过期）；原子操作内嵌文件随表单序列化保存，不受影响。

### 4.4 创建幂等键改为内容哈希（前端）

- 原实现：按"用户+项目"在 sessionStorage 存一个 UUID，创建失败不清除，修改内容重试触发后端 409。
- 新实现：`creationIdempotencyKey(payload)` 对请求体（业务字段+说明+附件 ID 列表）做 cyrb53 风格哈希，键为 `create-{user}-{project}-{hash}`。相同内容重试命中同一键（后端回放返回首次创建的 WKD），内容变化自然落到新键。
- 创建成功后仍调用 `clearCreatedSessionReferences()` 清理上传会话引用；幂等键不再需要 sessionStorage 存储。

### 4.5 原子操作编排交互（前端）

- 卡片去掉 `draggable`，仅头部 `⠿` 手柄 `draggable="true"` 触发拖拽；卡片保留 `dragover/drop` 接收放置，`dropOperation()` 逻辑不变。
- 拖拽中卡片 `opacity:.55` + 虚线边框反馈。
- 编排区标题栏新增 `operation-count` 徽章"已添加 X 个操作"，人工执行类型下隐藏。

### 4.6 属性面板与杂项（前端）

- 属性面板分组顺序调整为：基本信息 → 执行属性 → 业务归属；移除备注输入框（后端 `remark` 字段保留兼容，不传即为 `null`）。
- 关联机台 `el-select` 增加 `filterable` + `collapse-tags`。
- `HomeView.vue` 移除「登记 WKD」按钮，新建唯一入口为工作台。
- `LoginView.vue` 左侧品牌面板增加 `justify-content: center`。
- 新增 `scripts/dev-services.sh`：一键管理工程内自带的 PostgreSQL 17 / RustFS / 后端(8000) / 前端(7100)，含就绪探测，日志在 `.cache/services/logs/`。该目录不进 Git。

## 5. 部署与升级注意事项

- 数据库结构无变化，v1.7 → v1.8 直接替换代码重启即可；回滚无数据结构障碍。
- 后端启动即生效的变更：状态枚举校验、行锁修复。前端需重新构建 `dist`。
- 本地开发可直接使用 `./scripts/dev-services.sh start`（数据与二进制在 `.cache/services/`，已从 Git 排除）。
- 生产配置项无新增、无变更。

## 6. 测试结果

- 后端：`npm run backend:test` 130 项全部通过（含新增 3 项资源状态校验回归）。
- 前端：`npm run test:frontend` 2 项通过；`vue-tsc --noEmit` 无错误；`npm run build` 成功（仅既有 chunk 体积警告）。
- 实库验证：本地 PostgreSQL 上执行 `select(Wkd)...with_for_update(of=Wkd)` 行锁成功；登录后用 `RUNNING` 创建机台成功、`DEVELOPING` 被 422 拒绝。

## 7. 已知限制

- 草稿为单槽位：同一用户同时只能有一份新建草稿；附件不随草稿恢复。
- 幂等键哈希为前端本地计算，仅用于防重复创建，不具备保密性需求。
- 数据统计仍不做权限管控（v1.7 既定行为），任何人可查看与导出。
