# WMP v1.6 整体设计与代码审查及修复报告

- 审查与修复版本：v1.6.0
- 日期：2026-10-28
- 范围：整体架构、认证与 RBAC、WKD 生命周期、原子操作、附件、调试／正式构建、统计、系统管理、前端交互、性能与生产部署
- 验证方式：静态调用链审查、后端自动化回归、独立边界测试、前端 TypeScript 检查与生产构建

## 1. 结论

本轮发现的问题已按“授权与交付一致性 → 并发与管理员安全 → 读模型与生产配置 → 构建、统计与文件限制 → 输入校验和前端交互”的顺序完成修复。现有六状态生命周期、项目内 RBAC、附件直传和可执行规避包架构保留，没有推倒重做。

当前后端回归为 **127 项全部通过**，前端 `vue-tsc --noEmit` 与 Vite 生产构建通过。构建仍有 Element Plus、ECharts 大 chunk 警告，不影响构建成功。

本轮不能把系统表述为已经完成全部生产加固：统计仍是应用层全量聚合，构建仍是同步请求，Alembic、统一业务时区和登录限流尚未落地；真实 PostgreSQL 双事务并发、RustFS 压测及浏览器竞态也未做环境实测。残余边界见第 4 节。

## 2. 已修复问题与验收结果

### P0：授权与交付一致性

#### F01 全局角色现在真正参与鉴权

- 有效角色统一为“具体项目成员角色优先，无该项目成员关系时回退全局角色”。
- 鉴权、可访问项目、权限查询、基础选项和责任人选项共用该语义。
- 全局软件经理可以成为项目审核人；已经分配项目角色的用户不会被全局角色覆盖。
- 停用项目和初始化项目继续禁止实际业务。

#### F02 附件上传遵守明确的状态边界

| WKD 状态 | 上传规则 |
|---|---|
| `NEW_WKD`、`VERIFY` | 当前处理人可上传，同时要求 `wkd.edit` 与 `files.upload` |
| `REVIEW` | 禁止，返回 `409` |
| `APPROVED` | 允许具有 `files.upload` 的项目用户受控补传资料 |
| `DISABLE_CONFIRM`、`DISABLED` | 禁止，返回 `409` |

- 创建会话、初始化上传、申请分片地址和完成上传都会重新校验状态。
- 既有 WKD 的会话操作会锁定 WKD，旧会话不能跨状态完成上传。
- APPROVED 补传是受控资料变更，不修改业务字段、不触发状态流转，也不递增 `lock_version`；构建仍读取当前已绑定的 READY 附件。
- 前端按钮显示规则与服务端一致。

### P1：并发、安全、性能和构建

#### F03 状态流转使用强制、原子的乐观锁

- 所有流转请求必须携带 `lock_version >= 1`，不再允许缺省。
- 后端通过 `SELECT ... FOR UPDATE` 锁定目标 WKD，再比较版本；冲突返回 `409`。
- 状态或处理人变化时递增版本，避免两个请求基于同一快照互相覆盖。

#### F04 重名账号和管理员初始化边界收紧

- 本地登录支持用户名或唯一工号；用户名重名时明确提示使用工号。
- 初始化管理员优先按 `BOOTSTRAP_ADMIN_EMPLOYEE_ID` 定位，不再仅凭可重复用户名提升普通账号。
- 已有超级管理员保留兼容接管逻辑，避免升级后丢失唯一管理员入口。

#### F05 高频读模型移除 Base64 和完整快照放大

- 工作台列表、构建候选、统计明细、首页最近与待办均使用轻量 WKD DTO，不返回 `operations`。
- 工作台标签计数和首页指标改用 SQL `COUNT`。
- 制品列表延迟加载并不返回 WKD 快照正文；完整编排只在详情和实际构建时读取。
- 统计导出已进一步改为标准 XLSX 工作簿；后端使用临时文件缓冲并流式返回，不把整份工作簿一次性放入内存。

#### F06 生产配置 fail-closed

生产启动会拒绝以下不安全配置：

- 默认或长度不足 32 字符的 JWT 密钥；
- 默认或长度不足 12 字符的管理员初始密码；
- 默认 RustFS 访问键或密钥；
- 默认数据库账号密码组合。

新增 `BOOTSTRAP_ADMIN_EMPLOYEE_ID` 和 `MAX_BUILD_ATTACHMENT_BYTES` 配置，并同步部署示例。

#### F07 构建增加预算、补偿，入口脚本降低资源占用

- 单次构建最多 200 个不重复 WKD。
- 普通附件总大小默认最多 2 GB，可通过 `MAX_BUILD_ATTACHMENT_BYTES` 调整。
- RustFS 上传成功后若数据库提交失败，会补偿删除已上传对象；补偿失败仍需对象存储生命周期策略兜底。
- 通用入口以流式方式哈希和复制文件，使用临时文件与 `os.replace` 避免半写入文件。
- Linux 命令实时输出；超时终止进程组，不再使用 `capture_output=True` 缓存全部输出。

尚未完成构建任务化、幂等和进度查询，不能宣称已经解决所有长请求与重复提交问题。

#### F08 统计审核趋势按事件发生周期计算

- 新增趋势继续按 WKD 创建时间统计。
- 审核趋势独立查询 APPROVE 事件，以前创建、本周期审核的 WKD 会计入本周期。
- 页面指标改名为“当前审核通过占比”，明确它不是严格的历史流转转化率。
- XLSX 对公式危险前缀进行中和，前端 Demo XLSX 使用同样规则。

#### F09 原子文件与代理限制统一

- 单个原子文件上限 20 MB，每个上传操作 1～100 个文件，单 WKD 原子文件总量上限 100 MB。
- Nginx `client_max_body_size` 调整为 `160m`，容纳 Base64 放大及其余表单字段。
- 普通大附件继续走 RustFS 直传／分片，不经过 JSON。

### P2：业务约束、输入安全与交互

#### F10 基础数据状态参与业务校验

归档所属版本、停用子系统、停用机台不能用于新建或重新编辑业务关系；停用项目和初始化项目禁止实际业务。历史关联数据仍保留查看与追溯能力。

#### F11 原子操作和基础数据输入校验收紧

- 普通阶段自动清空自定义阶段名；自定义阶段使用安全 ASCII 脚本参数格式。
- 上传目标路径和 Linux 工作目录必须是不含 `..` 的绝对路径。
- 超时为 1～86400 秒整数，期望退出码为 0～255 整数。
- 脚本类型仅支持 Python、Shell；Linux 命令继续禁止环境变量参数。
- 问题单号、需求单号、实体名称、编码、状态、日期等增加长度、枚举或格式校验。

#### F12 XLSX 导出与公式中和

后端统计导出和前端 Demo 导出均生成标准 `.xlsx`，处理 `=、+、-、@` 及前导空白后的公式前缀，避免 Excel 打开时把用户文本执行为公式。工作表提供冻结表头、自动筛选和适配列宽；测试使用 openpyxl 重新打开文件，核对工作表、行列数、单元格文本类型和筛选范围。

#### F13 草稿和上传交互修复

- 新建附件会话和创建幂等键改用 sessionStorage，并按标签页隔离，避免多标签页串附件。
- 按钮改为“保存本地草稿”；超过 4 MB 的草稿明确拒绝并提示直接提交，不再静默失败。
- 上传增加 120 秒 XHR 超时、指数退避和 AbortSignal 取消。
- 分片断点恢复仍未实现。

#### F14 项目切换和列表请求竞态控制

选项、权限和工作台列表请求使用递增序号，仅接受最新上下文与最新请求的结果，避免旧响应覆盖新项目或新筛选条件。该修复通过代码路径审查，未做浏览器自动化竞态实测。

#### F15 占位通知入口隐藏

未实现的通知中心入口和对应前端脚本已隐藏、清理，避免把“尚未实现”误解为“没有通知”。现有空通知兼容接口未作为真实通知能力宣传。

#### F16 首屏按需加载

业务页面改为路由级懒加载，ECharts 独立 chunk 不再由登录首屏直接加载。Element Plus 与 ECharts 仍存在大 chunk 警告，后续可继续做组件级拆包。

#### F17 内网 HTTP 的 UUID 兼容

- 新增 `src/utils/id.ts`：优先使用 `crypto.randomUUID()`，在非安全上下文不提供该 API 时，通过 `crypto.getRandomValues()` 生成兼容的 RFC 4122 v4 UUID，并保留最终随机回退。
- WKD 原子操作、创建幂等键、历史与附件 Demo 记录，以及成员、角色和 Demo 构建统一使用该入口，避免只修复“添加”后在后续保存再次失败。
- 浏览器回归中主动将 `crypto.randomUUID` 设为不可用，确认“添加到当前阶段”仍新增上传文件卡片，生成的 ID 合法且不重复。localhost 属于安全上下文，不能单独作为内网 HTTP 兼容性验收依据。

#### F18 富文本斜体、默认颜色与工具栏

- 根因是全局 `font-synthesis: none` 禁止合成斜体，同时字体资源没有斜体变体；并非 `execCommand('italic')` 未执行。现改为允许样式合成。
- 编辑区默认黑色 14 px，颜色控件默认黑色，并与加粗、斜体、下划线放在同一工具组。
- 浏览器实测斜体生成 `<i>` 标签且计算样式为 `italic`；前后端富文本白名单清洗逻辑保持不变。

#### F19 顶部上下文与详情页信息降噪

- 项目和版本下拉框统一桌面宽度为 240 px，窄屏等宽自适应，并均支持输入搜索。
- 详情页“字段属性”改为“属性”；责任人和当前处理人移除头像、锁图标及附属提示，改为整行只读输入框，显示“用户名 工号”。
- 删除“编号按日自动生成”“状态说明与流转”等重复文案；占位提示仅保留目标目录 `/root/temp` 和权限 `0644` 等格式示例。详细流程直接展示状态面板，不再重复解释页签用途。

### P3：文案与语义修正

- 表格字段偏好文案明确为“当前浏览器”，不暗示跨设备同步。
- 首页“今日待办”改为“我的待办”，与无单日时间条件的实际口径一致。

## 3. 保留的合理设计

1. 六状态各自独立，流转动作、权限和当前处理人约束均由服务端执行。
2. 项目管理员不能分配、修改或移除系统管理员，最后一名项目管理员有专项保护。
3. OIDC 保留授权码、State、Nonce、Issuer、Audience、ID Token 签名和 UserInfo 主体校验。
4. 创建幂等、草稿附件归属校验和绑定行锁继续保留。
5. 普通大附件使用 RustFS 直传／分片；构建流式读取并校验大小和 SHA-256。
6. 自动化和人工 WKD 均可构建；普通附件只随包携带，不自动执行。
7. 富文本继续使用前后端双重清洗。

## 4. 尚未完成的残余风险与后续建议

| 优先级 | 残余项 | 当前边界与建议 |
|---|---|---|
| 高 | 同步构建 | 大构建仍受请求和代理超时影响，且无幂等、进度查询；建议改为后台任务并限制并发 |
| 高 | 统计扩展性 | 指标、分布和明细仍在应用层全量聚合，明细未后端分页；大数据量前改 SQL 聚合与游标／分页 |
| 高 | 数据库演进 | 仍使用 `create_all` 与启动 DDL；建议引入 Alembic，并验证多实例升级与回滚 |
| 中 | 时间语义 | naive UTC 与服务器本地日期仍混用；需统一 UTC 存储和明确业务时区 |
| 中 | 登录防护 | 生产仅允许管理员本地登录，但尚无 IP／账号限流、失败锁定和告警 |
| 中 | 上传体验 | 已支持超时、退避和取消，未实现分片断点恢复 |
| 中 | 探针 | `/health` 是存活检查，不验证 PostgreSQL 与 RustFS；建议增加独立 readiness |
| 低 | 前端包体 | 路由和图表已懒加载，但大型 vendor chunk 警告仍在 |
| 低 | 用户偏好 | 表格列偏好仅当前浏览器保存，不支持跨设备同步 |

- 既有构建包测试继续覆盖 Hello／World 原子文件、默认阶段顺序、自定义阶段、人工 WKD 普通附件、二进制内容和附件 SHA-256 校验。

## 6. 当前交付判断

授权、附件状态、原子乐观锁、管理员初始化、轻量读模型、生产默认配置、构建预算与统计事件口径等本轮阻断项已形成代码和测试闭环。可以继续受控联调与小范围验证，但在扩大生产数据量和并发前，应优先完成**构建后台任务化、统计数据库聚合与明细分页、Alembic 迁移**，并补足真实基础设施和浏览器端验收。
