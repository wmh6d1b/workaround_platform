# WMP v1.7 累计差异、部署与代码理解指南

本文面向内网 AI、研发和运维人员，说明当前 **v1.7.0** 相比 GitHub **v1.5.0** 的累计变化。行为结论来自当前代码与测试，精确逐行差异见 `docs/v1.7-full.diff`；历史版本文档保持原貌，不回写为 v1.7。

## 1. 对比基线与阅读方式

- 基线提交：`af58f6fd7082f9f42299831d6424c06f415d2f7b`（`release: WMP v1.5.0`）。
- 中间版本：v1.6 已完成构建交付、权限与并发加固、统计 XLSX、附件边界和内网交互修复，详见 `docs/v1.6-change-guide.md`。
- 当前版本：v1.7.0，重点修复普通成员首屏项目上下文与权限竞态，补齐设计、开发、测试、部署和截图培训材料。
- `docs/v1.7-full.diff` 直接从 v1.5 基线生成，不是 v1.6 diff 的增量拼接；不包含 diff 文件自身、PPTX 和培训截图等二进制内容。
- 接口以 `docs/api.md`、`docs/openapi.json` 为准；部署以 `docs/deployment.md` 为准，不要根据页面或历史文档推测。

## 2. 一句话理解 v1.7

v1.7 保留 v1.6 的业务模型和接口，在其基础上确保“真实项目与版本确定、当前项目权限刷新完成后才挂载业务页面”，同时消除并发选项请求、旧项目权限覆盖和侧栏冗余状态展示。

## 3. v1.5 → v1.7 用户可见行为差异

| 场景 | v1.5 | 当前 v1.7 |
|---|---|---|
| 普通成员首次进入或刷新页面 | 页面可能先使用占位项目上下文，再补加载真实数据 | 身份、真实项目选项和当前项目权限就绪后才挂载业务页面 |
| 首页与布局同时初始化 | 可能重复请求选项，页面需要自行补救上下文 | 非强制 `ensureOptions()` 并发调用共享同一请求 |
| 快速切换项目 | 迟到的旧响应存在覆盖新项目状态的风险 | 选项和权限均校验请求序号、项目及会话，旧结果被忽略 |
| 收起侧栏后的构建入口 | 悬停或浮层行为容易造成布局突出 | 使用居中标准菜单图标，按权限进入调试或正式构建 |
| 侧栏底部 | 展示“API 已连接”等状态文字 | 移除无业务作用的状态区，仅保留收起／展开导航 |
| 阶段执行 | 逐个输入 WKD 编号与阶段 | 默认 `wmp_entry.py <阶段参数>` 按清单顺序执行匹配 WKD |
| 查看构建包 | 无独立列表入口 | `wmp_entry.py --list` 查看编号、阶段、操作数和标题 |
| 单 WKD 执行 | 两个位置参数 | 推荐 `<阶段参数> --wkd <编号>`，旧双位置参数仍兼容 |
| 人工 WKD 与普通附件 | 构建交付不完整 | 可构建独立子包，`READY` 普通附件随包携带但不自动执行 |
| 统计导出 | CSV | 标准 XLSX，复用当前全部筛选条件并中和公式危险前缀 |
| 内网 HTTP 原子操作 | 部分浏览器因 UUID API 不可用而无响应 | 使用跨安全上下文 UUID 生成入口 |
| 详情页与富文本 | 头像、重复提示和格式交互不统一 | 精简属性区，修复斜体、默认黑色与字体颜色工具栏 |
| 表格 | 可选列与表头筛选能力有限 | 工作台和构建页支持列偏好、表头搜索、多选、全选与清空 |

## 4. v1.7 相对 v1.6 的关键实现

### 4.1 首屏初始化门禁

`src/layouts/AppLayout.vue` 新增 `contextReady`，顺序固定为：

```text
refreshIdentity()
  → ensureOptions() 确定真实项目、版本和基础选项
  → 初始化项目路由检查
  → refreshPermissions() 刷新当前项目权限
  → contextReady = true，挂载 router-view
```

门禁完成前只显示加载状态。这样避免业务组件在 `setup`／`onMounted` 中携带 `demo-project`、`demo-version` 或旧项目权限发起真实请求。

### 4.2 选项请求合并与竞态处理

`src/store.ts` 新增 `optionsInFlight`：

- 非强制并发调用共享同一个 Promise，调用方返回时真实项目已经写入 store。
- `force=true` 仍用于项目切换，不被普通读取合并。
- `optionsRequest` 只接受最新选项结果；`permissionsRequest`、项目 ID 和会话共同防止旧权限覆盖。
- 请求结束后只清理自己对应的进行中 Promise，避免误清理后续请求。

### 4.3 页面与侧栏调整

- `src/views/HomeView.vue`：加载首页数据前等待 `ensureOptions()`。
- `src/components/system/RoleManagement.vue`：角色数据加载前等待真实选项，支持直接刷新系统管理页面。
- `src/layouts/AppLayout.vue`、`src/styles/index.css`：收起状态使用标准居中菜单项，删除构建浮层专用样式和“API 已连接”区域。
- `package.json`：新增 `npm run test:frontend` 和开发依赖 Vitest；生产运行不依赖 Vitest。

### 4.4 新增固定回归

`src/store.test.ts` 覆盖两个 P0 场景：

1. 首页和布局并发初始化只请求一次选项，任一调用返回时真实项目均已就绪。
2. 项目 A 权限晚于项目 B 返回时，不得覆盖项目 B 权限。

后续修改登录、布局、路由、store 或页面初始化时不得删除这两项回归。

## 5. 后端与数据库是否变化

- v1.7 相对 v1.6 **没有新增业务路由、请求字段、权限点或数据库结构变化**；仅应用和接口文档版本号从 `1.6.0` 升级为 `1.7.0`。
- v1.5 → v1.7 累计仍为 **56 个接口操作、48 条路径**。当前 OpenAPI 快照为 OpenAPI 3.1.0／v1.7.0。
- 从 v1.5 升级不需要执行 v1.6／v1.7 专属数据库迁移；后端仍使用启动时 `create_all` 与幂等 DDL，尚未引入 Alembic。
- v1.6 引入的 `BOOTSTRAP_ADMIN_EMPLOYEE_ID`、`MAX_BUILD_ATTACHMENT_BYTES` 配置继续保留，升级时按 `backend/.env.example` 核对。
- 如果从 v1.5 之前的版本升级，仍需先核对 v1.5 的用户部门、用户名约束及旧 `users.name` 列变化。

## 6. 部署升级步骤

1. 固定 v1.7 发布提交并备份 PostgreSQL、RustFS 和当前环境配置。
2. 测试与生产继续使用独立数据库、Bucket、JWT 密钥、OIDC Client 和管理员密码。
3. 前端执行 `npm ci && npm run build`，将 `dist/` 交给 Nginx；不要在生产运行 Vite 或开启 Demo 登录。
4. 后端按 `backend/requirements.txt` 安装依赖并更新 `.env`，不需要新增 v1.7 专属 Python 包。
5. 启动后检查 `/health` 返回 `version: 1.7.0`，并核对 `/openapi.json` 与 `docs/openapi.json`。
6. 必须使用**普通项目成员**执行全新 OAuth 会话首屏验收，不能用系统管理员代替：
   - 首页、工作台、新建 WKD、调试构建、正式构建、统计、成员和角色页面可冷启动及直接刷新。
   - 请求中不得出现 `project_id=demo-project` 或 `demo-version`。
   - 不得误报“你不是该项目成员”，首页与统计首屏不得重复请求选项。
7. 快速切换项目并制造慢响应，确认旧项目数据和权限不覆盖新项目；后端仍须独立拒绝非成员访问。
8. 继续执行 v1.6 的制品验收：`--list`、整包阶段执行、单 WKD、人工附件、SHA-256 和隔离环境验证。

完整 Nginx、systemd、RustFS CORS、OIDC 和回滚约束见 `docs/deployment.md`。

## 9. 当前验证结果

2026-10-29 在当前 v1.7 工作区实际执行：

- `npm run test:frontend`：1 个测试文件、2 项测试全部通过。
- `npm run backend:test`：127 项测试全部通过。
- `npm run build`：TypeScript 检查与 Vite 生产构建通过。
- `npm run docs:api`：成功导出 56 个接口操作，JSON 校验通过。
- 构建仍有 Element Plus、ECharts、ExcelJS 大 chunk 警告，不影响构建成功。

自动化结果不能替代真实内网 OIDC、RustFS CORS、弱网、多标签页、大文件和高并发验收。

## 10. 升级后仍需关注的边界

1. 构建仍为同步请求，没有后台进度和构建幂等。
2. 统计仍在应用层全量聚合，明细未后端分页。
3. 数据库尚未引入 Alembic，启动 DDL 需要相应权限并先备份验证。
4. 时间字段仍有 naive UTC 与服务器本地日期混用。
5. 本地管理员登录尚未实现限流、失败锁定和告警。
6. 分片上传支持重试，但不支持跨会话断点恢复。
7. `/health` 仅表示进程存活，不代表 PostgreSQL 与 RustFS readiness。

## 11. 推荐阅读顺序

1. 内网 AI 先读本文第 2～6 节，建立行为与部署差异模型。
2. 修改首屏或权限前读 `docs/development-frontend.md` 第 3～4 节和 `src/store.test.ts`。
3. 精确核对代码时打开 `docs/v1.7-full.diff`，再按第 7 节定位当前文件。
4. 上线前读 `docs/deployment.md` 和 `docs/testing.md`，用普通成员完成 P0 验收。
5. 培训用户使用 `docs/training-wmp/training-wmp.pptx`，不再依赖文字想象页面操作。
