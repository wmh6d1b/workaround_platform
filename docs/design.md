# WMP v1.7 设计文档

- 文档日期：2026-10-29
- 适用版本：v1.7.0
- 文档边界：描述当前已实现能力；残余限制单列，不作为已交付能力宣传。

## 1. 设计目标

WMP 用于登记、审核、交付和追溯规避措施（WKD），核心目标为：

1. 以项目、版本、机台和子系统建立明确业务边界。
2. 以六状态状态机约束 WKD 从新建到审核通过或禁用。
3. 将自动化规避内容编排为有序原子操作，并生成可独立解包执行的 `tar.gz` 制品。
4. 所有业务按钮均由服务端按项目有效角色鉴权，前端仅负责呈现。
5. 附件、历史、构建快照和审计记录可追溯到具体用户、项目和状态。

## 2. 总体架构

```text
Vue 3 + TypeScript + Element Plus
              │ 同源 /api/v1，Bearer Token
              ▼
       FastAPI + SQLAlchemy
        │             │
        ▼             ▼
   PostgreSQL       RustFS（S3 兼容）
   业务数据          附件与构建制品
   权限/历史         私有对象 + 预签名 URL
```

- 前端生产构建为静态文件，由 Nginx 托管；不运行 Vite。
- 后端只监听内网地址，由 Nginx 反向代理。
- 普通附件由浏览器通过预签名地址直传 RustFS，不经过后端 JSON。
- 构建时后端读取数据库快照与 RustFS 对象，生成真实制品并记录 SHA-256。
- 企业 OIDC 负责普通用户身份认证，WMP 负责项目与按钮授权；系统管理员使用本地管理员登录。

## 3. 核心领域模型

### 3.1 业务关系

- 项目一对多关联版本、机台、子系统和 WKD。
- 一个 WKD 只属于一个项目、一个所属版本和一个子系统，可关联多个机台。
- 责任人是首次创建 WKD 的当前用户，不另设创建人，不允许后续变更。
- 一个 WKD 只有一个执行阶段；阶段内包含多个按 `position` 排序的原子操作，所有关联机台共用该编排。
- 构建制品与 WKD 为多对多关系，制品明细保存顺序与不可变快照。
- 用户可拥有具体项目成员角色；无该项目成员关系时，回退到独立的全局角色。

完整字段、校验和附件约束见 `docs/data-model.md`。

### 3.2 WKD 字段规则

- 问题单号与需求单号至少填写一项；填写问题单号时问题发现版本必填。
- 执行类型为自动化执行或人工操作；自动化必须有阶段和至少一个原子操作，人工操作不保留阶段和编排。
- 活动场景为首版本部署、ES 集成活动或常规版本升级。
- 类型为事前规避措施或事后恢复措施。
- 自定义阶段名在当前所属版本内唯一，并采用可直接作为脚本参数的 ASCII 安全格式。
- 项目、所属版本和责任人创建后不可修改。

## 4. 生命周期设计

```text
NEW_WKD ──提交自验证──> VERIFY ──提交审核──> REVIEW ──通过──> APPROVED
   │                      │                     │                │
   │                      │                     └──驳回──> VERIFY │
   │                      │                                      ├─发起禁用─> DISABLE_CONFIRM
   │                      │                                      │                │
   └────────直接禁用──────┴──────────────> DISABLED <──确认禁用───┘                │
                                                                  拒绝禁用──────────┘
```

| 状态 | 当前处理人 | 业务编辑 | 附件 |
|---|---|---|---|
| `NEW_WKD` | 责任人 | 本地编辑，提交时写入 | 当前处理人按权限上传 |
| `VERIFY` | 责任人 | 本地编辑，提交时写入 | 当前处理人按权限上传 |
| `REVIEW` | 指派软件经理 | 锁定 | 禁止 |
| `APPROVED` | 无 | 业务字段只读 | 允许受控补传 |
| `DISABLE_CONFIRM` | 指派软件经理 | 锁定 | 禁止 |
| `DISABLED` | 无 | 最终只读 | 禁止 |

- 每次流转必须携带 `lock_version`；后端使用行锁与版本比较防止并发覆盖。
- 提交自验证和提交审核携带完整 WKD 数据，后端同事务保存属性差异、状态和处理人。
- 审核、禁用申请和禁用确认意见均必填。
- 不提供取消或删除 WKD；审核通过后的业务纠错通过禁用后重建完成。

## 5. 权限设计

### 5.1 有效角色解析

```text
系统管理员 → 全部权限
普通用户   → 当前项目存在成员记录：使用项目成员角色
           → 当前项目无成员记录：使用 users.global_role_id 对应角色
```

- 全局角色开放正常项目的回退访问能力，但不覆盖明确分配的项目角色。
- 项目角色与全局角色不冲突：全局“开发人员”可以在某个项目被明确分配为“软件经理”。
- 系统管理员不是可分配项目角色；项目管理员不能修改或移除系统管理员成员。
- 项目必须至少保留一名项目管理员。

### 5.2 权限边界

- 系统管理员：项目、全局用户授权、全局角色模板和审计日志。
- 项目管理员：仅当前项目的版本、机台、子系统、成员与角色分配。
- 开发人员／软件经理／自定义角色：按角色权限点执行页面和按钮操作。
- 数据统计：按当前产品决策向所有已登录用户开放，不配置项目角色权限点。
- 用户初始化项目：仅用于 OAuth 账号落地，任何用户均不能在其中开展实际业务。

## 6. 前端上下文初始化设计

首屏必须满足以下顺序，禁止业务页面使用初始占位项目发起请求：

```text
读取本地会话
  → 刷新当前用户身份
  → 获取并确定真实项目、版本和基础选项
  → 刷新当前项目权限
  → 挂载业务页面并加载业务数据
```

- `AppLayout` 在上述步骤完成前不挂载 `router-view`。
- `ensureOptions()` 合并非强制并发请求；页面与布局同时调用时共享同一 Promise。
- 强制刷新仍用于项目切换；请求序号保证只接受最新结果。
- 权限响应同时校验请求序号、项目 ID 和当前会话，旧项目响应不得覆盖新项目。
- 前端隐藏或禁用按钮只是体验优化，后端仍需独立鉴权。

## 7. 原子操作与制品设计

支持三类原子操作：

| 类型 | 主要参数 | 约束 |
|---|---|---|
| 上传文件 | 目标目录、覆盖策略、权限、实际文件列表 | 单操作多选 1～100 个文件，保留二进制内容 |
| Linux 命令 | 命令、工作目录、超时、期望退出码 | 无环境变量参数，工作目录为安全绝对路径 |
| 脚本 | Python／Shell、脚本正文、参数、超时 | 仅支持明确脚本类型 |

制品包含通用 `wmp_entry.py`、`MANIFEST.json`、`WKD_LIST.json`、说明和各 WKD 独立子包。默认按 WKD 创建时间升序执行匹配阶段的子包，子包内按操作序号执行；普通附件只随包携带，不自动执行。

## 8. 附件与一致性设计

- 新建 WKD 前即可创建上传会话并上传草稿附件。
- 小于 64 MB 默认单次直传，达到阈值后采用 16 MB 分片；后端核验对象、大小和 SHA-256 后标记 `READY`。
- 创建 WKD 时显式绑定当前用户、当前项目、未绑定且 `READY` 的附件。
- 创建幂等键防止网络重试产生重复 WKD。
- 上传会话默认 24 小时过期；后端定时清理过期未绑定对象，RustFS 生命周期规则作为分片清理兜底。
- 数据库存业务元数据和 Object Key，RustFS 存二进制；备份与恢复必须覆盖两者。

## 9. 查询、统计与性能边界

- 工作台、首页、构建候选、统计明细采用轻量 DTO，不返回完整原子编排。
- 高频计数使用 SQL 聚合；完整操作只在详情和实际构建时读取。
- 表格列偏好按“用户＋表格类型”保存在当前浏览器，不同步到服务端。
- 统计支持项目／全局范围、多选筛选、趋势、分布、明细和 XLSX 导出，所有输出共用同一筛选条件。
- 当前统计仍在应用层全量聚合且明细未后端分页；构建仍为同步请求。扩大数据量前应优先优化这两处。

## 10. 安全与审计

- OIDC 使用授权码、State、Nonce、Issuer、Audience 和 ID Token 签名校验。
- 已导入用户首次仅按工号绑定 OIDC `sub`，后续按 `sub` 识别，禁止用可重复用户名替代绑定。
- 生产配置采用 fail-closed，拒绝默认密钥和弱管理员初始密码。
- 富文本前后端双重清洗；XLSX 导出中和公式危险前缀。
- 重要操作写审计日志；构建记录保存快照、文件大小和 SHA-256。

## 11. 已知限制

1. 构建未任务化，无后台进度和构建幂等。
2. 统计尚未 SQL 全量聚合和明细分页。
3. 数据库尚未引入 Alembic，启动时执行 `create_all` 与幂等 DDL。
4. 时间字段仍有 naive UTC 与服务器本地日期混用。
5. 本地管理员登录尚未实现限流、失败锁定和告警。
6. 分片上传支持重试，但不支持跨会话断点恢复。
7. `/health` 仅表示进程存活，不代表 PostgreSQL 与 RustFS readiness。
