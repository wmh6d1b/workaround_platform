# WMP v1.6 详细差异与代码阅读指南

本文面向内网 AI、研发和运维人员，说明当前 **v1.6.0** 相比 GitHub **v1.5.0** 的累计变化。当前完整逐行补丁见 `docs/v1.6-full.diff`，包含首次 v1.6、整体审查修复以及后续浏览器兼容与界面精简；残余边界见 `docs/v1.6-design-code-review.md`。接口、数据模型和部署约束分别以对应专题文档为准。

## 1. 对比基线与结论

- 基线提交：`af58f6fd7082f9f42299831d6424c06f415d2f7b`
- 基线提交说明：`release: WMP v1.5.0`
- 基线位置：GitHub `origin/main`，与本地 v1.5 HEAD 已核对一致。
- 对比终点：当前 v1.6.0 工作区。
- 对比方式：读取基线 Git 对象，与当前工作区逐文件、逐行比较，不根据提交说明推断；`docs/v1.6-full.diff` 每次从同一基线重新生成，不叠加旧补丁。
- 首次 v1.6 既有文件变化为 15 个、合计 **+332 / -80 行**，该数字仅用于追溯首次上传；当前累计变化以完整 diff 为准。
- 接口操作仍为 **56 个（48 条路径）**，没有新增、删除或修改 API 路径；审查修复收紧了流转锁、原子参数和构建输入模型，当前 OpenAPI 以 `docs/openapi.json` 为准。
- 数据库：**没有表、字段、枚举或索引变化，不需要执行 v1.6 专属数据库迁移**。
- 当前前端新增 `exceljs` 用于 Demo XLSX 导出，后端 XLSX 使用 openpyxl；目标机通用入口仍只依赖 Python 标准库。

## 2. 一句话理解 v1.6

v1.6 不改变 WKD 六状态数据模型，累计完成构建交付升级、授权与并发加固、统计 XLSX、附件和输入边界修复，并补齐内网 HTTP 浏览器兼容、富文本及详情页交互。首次构建差异见下文，后续累计修复以审查报告和当前完整 diff 为准。

### 2.1 首次构建升级后的累计修复摘要

- 有效全局角色、附件状态边界、WKD 行锁、管理员唯一性、轻量 DTO、生产 fail-closed、构建预算与输入校验形成服务端闭环。
- 统计导出统一为标准 XLSX，包含公式中和、冻结表头、自动筛选与适配列宽。
- 项目和版本顶部下拉框等宽并支持输入搜索。
- 新增跨安全上下文的 UUID 生成入口，修复内网 HTTP 下添加原子操作无响应。
- 修复富文本斜体渲染，默认文字改为黑色，字体颜色与文字格式按钮同组。
- 详情页属性区改用“用户名 工号”只读输入框，移除头像、锁图标、重复标题和非必要 placeholder。

## 3. 用户可见行为差异

| 场景 | GitHub v1.5 | 当前 v1.6 |
|---|---|---|
| 执行整个阶段 | 必须逐个输入 `wmp_entry.py <WKD编号> <阶段参数>` | 默认 `wmp_entry.py <阶段参数>`，按登记顺序执行全部匹配 WKD |
| 只执行一个 WKD | 使用两个位置参数 | 推荐 `<阶段参数> --wkd <WKD编号>`；旧双位置参数仍兼容 |
| 查看包内内容 | 没有独立列表参数 | `wmp_entry.py --list` 显示编号、阶段、操作数和标题 |
| 阶段不匹配 | 单包直接报阶段不适用 | 整包模式自动跳过不匹配 WKD，并输出跳过数量 |
| 没有匹配 WKD | 不提供整包阶段执行语义 | 明确返回非零退出码，避免误报成功 |
| 人工操作 WKD | 自动化入口不能执行，构建内容也未完整承载普通附件 | 可以构建独立子包，保留属性、说明和普通附件；不会自动执行 |
| WKD 普通附件 | 不进入构建子包 | `READY` 附件进入 `attachments/`，并写入清单和哈希 |
| 大附件构建 | 构建接口不读取普通附件 | 从 RustFS 流式读取，经临时文件生成并上传制品，避免整包载入内存 |
| 附件完整性 | 构建包没有普通附件校验 | 打包时校验实际大小和 SHA-256；不匹配则构建失败 |
| 收起侧栏后经过“构建 / 发布” | 自动弹出 200 px 子菜单浮层 | 悬停不弹出；点击图标才显示调试／正式构建入口 |
| 收起侧栏后的构建导航 | 使用原 `el-sub-menu` 的弹出行为 | 使用独立点击菜单，当前构建页面保持图标高亮 |
| 工程版本 | `1.5.0` | `1.6.0`，仅显示在工程元数据、健康检查和接口文档中 |

## 4. 通用入口脚本详细差异

对应文件：`backend/app/templates/wmp_entry.py`。

### 4.1 新调用方式

```bash
# 只查看，不执行
python3 wmp_entry.py --list

# 按 MANIFEST.json 顺序执行该阶段下的全部 WKD
python3 wmp_entry.py post_start

# 自定义阶段直接传入自定义阶段名称
python3 wmp_entry.py <自定义阶段名称>

# 只执行一个 WKD
python3 wmp_entry.py post_start --wkd WKD202610270001

# v1.5 的旧调用仍然可用
python3 wmp_entry.py WKD202610270001 post_start
```

### 4.2 执行顺序和失败语义

1. 构建后端先按 WKD `created_at` 升序排列子包。
2. `MANIFEST.json` 保存这个顺序，入口按索引顺序执行，而不是按文件名字典序或用户输入顺序执行。
3. 默认只执行 `stage_parameter` 与当前阶段参数匹配的子包；其他子包打印 `[SKIP]`。
4. 每个子包内部仍按原子操作 `position` 升序执行。
5. 没有匹配项、单包不存在、阶段错误、文件校验失败或任一操作失败，都返回非零退出码。
6. 人工 WKD 没有自动化阶段，默认整包执行不会运行它；`--list` 将其阶段显示为“人工操作”。

## 5. 构建内容与附件详细差异

### 5.1 v1.6 制品结构

```text
wmp_entry.py
MANIFEST.json
WKD_LIST.json
README.md
packages/<WKD编号>/
├── package.json
├── files/...                         # 原子操作上传文件
└── attachments/<附件序号>/<文件名>    # WKD 普通附件，仅随包携带
```

- `package.json` 新增普通附件元数据列表 `attachments`。
- `MANIFEST.json` 的每个子包索引新增 `attachment_count`。
- `WKD_LIST.json` 同步包含附件清单，便于不展开子包时审计交付内容。
- 原子操作文件与普通附件继续分离；普通附件不会被入口自动执行、安装或覆盖到目标目录。
- 自动化 WKD 仍要求有效阶段参数；人工 WKD 允许无阶段、无原子操作打包。

### 5.2 流式构建与完整性校验

- `backend/app/storage.py` 新增 `read_object()`，返回 RustFS 对象流。
- `backend/app/builder.py` 新增哈希读取器，在写入 tar.gz 的同时累计实际大小和 SHA-256。
- 附件文件名继续进行路径安全校验，并按附件序号隔离，避免同名文件互相覆盖。
- 实际大小与数据库元数据不一致，或已有 SHA-256 与实际内容不一致时，构建返回错误，不生成“成功但损坏”的制品。
- `backend/app/routers/builds.py` 只查询所选 WKD 已绑定且状态为 `READY` 的附件。
- 生产构建路由通过临时文件承载 tar.gz，分块计算整个制品 SHA-256，再用 `upload_fileobj` 流式上传 RustFS。
- 构建审计增加本次打包的附件数量；原有按内存字节生成制品的兼容函数仍保留给测试或其他调用方。

## 6. 侧栏折叠交互详细差异

对应文件：`src/layouts/AppLayout.vue`、`src/styles/index.css`。

- 展开侧栏：保留原来的“构建 / 发布”分组及子项。
- 收起侧栏：不再渲染会自动悬停弹出的 `el-sub-menu`，改为独立 `el-dropdown`。
- 新菜单只在点击时打开，调试构建、正式构建的权限显示条件和路由地址保持不变。
- 收起按钮宽 48 px、高 46 px，图标尺寸、悬停色和激活色与其他导航一致。
- 已实测直接收起、展开子菜单后收起、收起后悬停三种场景；侧栏保持 72 px，无内部元素越界。
- 已实测收起后点击“调试构建”可进入 `/build/debug`，菜单关闭且图标保持激活高亮。

## 9. 测试差异

`backend/tests/test_build_package.py` 在原有构建测试上增加或扩展以下覆盖：

1. 默认整包执行严格遵循 `MANIFEST.json` 中的登记时间顺序。
2. `--list` 能列出不同阶段；整包执行会跳过不匹配项。
3. `--wkd` 只执行指定 WKD，不运行其他子包。
4. 没有任何匹配阶段的 WKD 时返回非零退出码。
5. 人工 WKD 可以打包，普通附件二进制内容、清单、数量和列表展示正确。
6. 普通附件 SHA-256 不匹配时构建失败。

首次 v1.6 后端回归为 108 项；整体审查修复后，当前完整后端回归为 **127 项测试**，前端继续执行 TypeScript 检查和生产构建。专项修复明细以 `docs/v1.6-design-code-review.md` 为准。

## 10. 升级注意事项

- 不需要修改数据库结构；审查修复新增 `BOOTSTRAP_ADMIN_EMPLOYEE_ID` 与 `MAX_BUILD_ATTACHMENT_BYTES` 配置，部署时应按当前 `backend/.env.example` 和部署文档补齐。
- 目标机仍只需要 Python 3 标准库；入口没有引入 Jinja2 或其他第三方依赖。
- 旧自动化系统仍可使用“WKD 编号 + 阶段参数”，但建议迁移到“阶段参数”整包调用，减少手工编号输入。
- 普通附件只用于交付和审计，不代表可执行内容；需要自动执行的文件仍必须明确编排为原子操作。
- 升级后应分别验证自动化 WKD、人工 WKD、带附件 WKD、无匹配阶段和附件哈希异常场景。
- 生产构建仍必须遵守原有项目、机台、状态和按钮权限校验；本版本没有放宽这些边界。

## 11. 推荐阅读顺序

1. 先读本文第 2～7 节，建立 v1.5 → v1.6 的行为差异模型。
2. 需要精确核对代码时打开 `docs/v1.6-full.diff`，再按第 8 节行号定位当前文件。
3. 构建实现依次阅读 `builds.py` → `builder.py` → `storage.py` → `wmp_entry.py`。
4. 上线前阅读 `docs/deployment.md` 的构建制品和侧栏验收步骤。
5. 接口集成仍以 `docs/api.md` 和 `docs/openapi.json` 为准，不要根据页面行为推测接口。
